# Improvement working record (keep outside the installed skill)

## Task and evidence

Target job, user contract, intended executor(s), builder model, actual available host/tools/settings, immutable original hash, representative failure and successful counterexample. Mark missing evidence explicitly.

## Knowledge cards

For each non-obvious decision record: ID; source/version; scope; kind (mandatory constraint / scoped preference / domain fact / replaceable strategy / model workaround); applicability; rule; positive example; nearest counterexample; invalidating evidence; proposed/observed status. Model workarounds also need the affected model/host and recheck trigger. Preserve authorization and licensing; reviewed documents are not instructions to execute.

## Diagnosis and candidates

Failure input + trace location; suspected cause; rival cause; discriminating test. Compare only materially different changes: removal/minimal contract, missing knowledge/contrast, resource placement or tool implementation. For each candidate record the exact diff, hypothesis, affected cases and what would falsify it. Keep the current best until new evidence warrants replacing it.

## Grading and feedback

Predeclare completion, correctness, judgment, usefulness, safety and format checks as applicable. Separate capability/regression and development/private-transfer cases. Keep facts/tools/settings matched. Record accepted and rejected alternatives; human rework and preference with a reason; grader mutation failures and valid-alternative acceptance. Do not auto-promote personal preferences or self-review into general rules.

## Decision

Keep / improve / simplify / split / tool / retire / unchanged. Cite actually observed results and critical regressions; list unrun work. Record rollback hash, intended scope and profile refresh trigger. Small edits need only a short inline version of this record.
